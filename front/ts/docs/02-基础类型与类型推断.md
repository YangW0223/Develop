# 02. 基础类型与类型推断

## 1. 原始类型

TypeScript 对应 JavaScript 常见原始值的类型包括：

```ts
const title: string = "TypeScript 入门";
const views: number = 1024;
const published: boolean = true;
const articleId: bigint = 9007199254740993n;
const uniqueKey: symbol = Symbol("article");
const empty: null = null;
const missing: undefined = undefined;
```

应使用小写 `string`、`number`、`boolean`，而不是包装对象类型 `String`、`Number`、`Boolean`。

## 2. 类型推断

编译器可以从初始值推断类型：

```ts
let score = 90;            // number
const course = "TS";       // "TS"，字面量类型
const topics = ["类型", "泛型"]; // string[]
```

`let` 的值可能被重新赋值，因此 `score` 被拓宽为 `number`。`const course` 不会指向其他值，所以它的类型可以精确到字面量 `"TS"`。

推荐：能正确推断时不重复书写类型。

```ts
const count = 1;         // 推荐
const count2: number = 1; // 合法，但信息重复
```

## 3. 字面量类型与联合类型

类型可以限制为某几个具体值：

```ts
type Theme = "light" | "dark" | "system";

let theme: Theme = "dark";
theme = "system";
// theme = "blue"; // ❌ 不在允许范围内
```

它比普通 `string` 更能表达业务规则，编辑器还会自动补全三个合法值。

数字字面量也适用：

```ts
type Dice = 1 | 2 | 3 | 4 | 5 | 6;
```

## 4. 数组与只读数组

两种数组写法等价：

```ts
const names: string[] = ["小明", "小红"];
const scores: Array<number> = [90, 95];
```

当函数不应修改传入数组时，使用只读数组：

```ts
function first<T>(items: readonly T[]): T | undefined {
  // items.push(...) // ❌ 只读数组不能修改
  return items[0];
}
```

`readonly` 是编译期约束，不会在运行时冻结数组。若需要运行时不可变，可使用 `Object.freeze`。

## 5. 元组

元组表示长度和每个位置类型已知的数组：

```ts
type Coordinate = [x: number, y: number];
const point: Coordinate = [120.5, 30.2];

const [longitude, latitude] = point;
```

带标签的 `x`、`y` 只改善提示，不影响赋值。适合少量、含义明确的位置数据；字段较多时对象通常更清楚。

只读元组常与 `as const` 一起出现：

```ts
const httpMethods = ["GET", "POST"] as const;
// 类型：readonly ["GET", "POST"]

type HttpMethod = (typeof httpMethods)[number];
// "GET" | "POST"
```

## 6. `any`、`unknown` 和 `never`

### `any`：关闭检查

```ts
let data: any = { name: "小明" };
data.notExists().anything; // 编译器不阻止，运行时可能报错
```

`any` 会沿调用链传播，应只在迁移遗留 JavaScript 等特殊场景短暂使用。

### `unknown`：值未知，使用前必须检查

```ts
function printValue(value: unknown): void {
  if (typeof value === "string") {
    console.log(value.toUpperCase());
  } else {
    console.log(String(value));
  }
}
```

外部输入、捕获的错误、解析后的 JSON 更适合使用 `unknown`。

### `never`：不可能出现的值

```ts
function fail(message: string): never {
  throw new Error(message);
}
```

函数永远不会正常返回，所以返回类型是 `never`。它也用于联合类型的完整性检查，第四章会展开。

## 7. `void`、`null` 与 `undefined`

`void` 常表示调用者不使用函数返回值：

```ts
function log(message: string): void {
  console.log(message);
}
```

开启 `strictNullChecks` 后，`null` 和 `undefined` 不能随意赋给其他类型：

```ts
let selectedId: number | null = null;
selectedId = 1;
```

常见约定：可选参数或缺少字段用 `undefined`，明确表示“空”可用 `null`。一个项目内保持一致比争论唯一答案更重要。

## 8. 类型断言与非空断言

类型断言告诉编译器你比它知道得更多：

```ts
const element = document.querySelector("#app") as HTMLDivElement | null;
```

断言不产生运行时检查。避免连续断言 `value as unknown as Target`，它通常在掩盖模型错误。

非空断言 `!` 会移除 `null | undefined`：

```ts
const app = document.querySelector("#app")!;
```

如果元素确实不存在，运行时仍会出错。更安全的写法是显式判断：

```ts
const app = document.querySelector("#app");
if (!app) throw new Error("缺少 #app 容器");
```
