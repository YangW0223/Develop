# 08. 模块、声明文件与第三方库

## 1. ES 模块

只要文件包含顶层 `import` 或 `export`，它就是模块，内部声明不会自动进入全局作用域：

```ts
// user.ts
export interface User {
  id: number;
  name: string;
}

export function displayName(user: User): string {
  return user.name;
}
```

```ts
// app.ts
import { displayName, type User } from "./user.js";

const user: User = { id: 1, name: "小明" };
console.log(displayName(user));
```

`import type` 明确表示只导入类型，编译结果中会被移除。在 Node.js 的 ESM 配置中，源码导入路径经常要写最终运行时的 `.js` 后缀，具体由 `moduleResolution` 决定。

## 2. 命名导出与默认导出

```ts
export const version = "1.0.0";
export function start(): void {}
```

命名导出在重构、自动导入和统一命名方面更清晰。默认导出适合一个文件确实只有一个主要概念的情况：

```ts
export default class App {}
```

一个项目内形成一致约定即可。

## 3. 仅类型位置与仅值位置

类同时存在于类型空间和运行时值空间：

```ts
class User {}

const user: User = new User();
//          ↑ 类型     ↑ 运行时构造函数
```

而 `type`、`interface` 只存在于类型空间：

```ts
interface Config { debug: boolean }
// console.log(Config); // ❌ 运行时没有 Config
```

理解两套空间有助于判断为什么某些符号不能用于 `instanceof` 或打印。

## 4. 第三方库的类型来源

依赖包的类型通常来自：

1. 包自身发布的 `.d.ts`。
2. 社区维护的 `@types/包名`。
3. 项目自己编写的声明文件。

例如一个旧 JavaScript 包没有类型，可先安装对应声明：

```bash
npm install package-name
npm install --save-dev @types/package-name
```

并不是所有包都有 `@types`；现代 TypeScript 包通常自带声明。

## 5. 声明文件 `.d.ts`

声明文件只描述类型，不包含业务实现。假设 `legacy-math` 是没有类型的 JavaScript 包：

```ts
// types/legacy-math.d.ts
declare module "legacy-math" {
  export function add(a: number, b: number): number;
}
```

这会让下面的调用得到检查：

```ts
import { add } from "legacy-math";

add(1, 2);
// add("1", 2); // ❌
```

声明必须与真实运行行为一致。错误的 `.d.ts` 比没有类型更隐蔽，因为它会给开发者错误信心。

## 6. 声明静态资源模块

某些构建工具允许直接导入资源，TypeScript 需要知道其含义：

```ts
// types/assets.d.ts
declare module "*.svg" {
  const url: string;
  export default url;
}
```

具体声明取决于工具：同一个 SVG 在某些项目中是 URL，在另一些项目中会被转换为组件，不能盲目复制。

## 7. 扩充已有模块

模块扩充用于为已有类型增加成员：

```ts
import "some-library";

declare module "some-library" {
  interface Options {
    traceId?: string;
  }
}
```

常见场景是插件为框架实例添加属性。扩充只改变类型描述，真实运行时代码仍必须安装或注册对应插件。

## 8. 全局声明

浏览器注入全局变量时，可以声明：

```ts
// global.d.ts
export {};

declare global {
  interface Window {
    analytics?: {
      track(event: string): void;
    };
  }
}
```

使用时仍要处理可选性：

```ts
window.analytics?.track("page_view");
```

尽量减少全局扩充，因为它会影响整个项目，并可能与其他库冲突。

## 9. Barrel 文件的取舍

`index.ts` 可以集中导出：

```ts
export { UserService } from "./user-service.js";
export type { User } from "./user.js";
```

它能简化公开 API，但大量内部 barrel 容易制造循环依赖、降低 tree shaking 可预测性。适合在包或模块的公共边界使用，不必为每个目录都创建。
