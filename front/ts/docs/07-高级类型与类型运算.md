# 07. 高级类型与类型运算

这一章不再停留在“记住几个工具类型”，而是学习如何从已有类型推导出新类型。高级类型的核心不是炫技，而是让类型定义与真实代码保持同步，减少重复和手写错误。

<a id="section-1"></a>
## 1. 先建立一个重要认识：类型也可以“计算”

普通代码在运行时计算值：

```ts
const total = price * quantity;
```

类型代码在编译时计算类型：

```ts
type User = {
  id: number;
  name: string;
};

type UserKeys = keyof User;
// "id" | "name"
```

`keyof User` 没有生成 JavaScript，它是在类型检查阶段把 `User` 的键计算成联合类型。后面看到的 `typeof`、`T[K]`、`T extends U ? X : Y` 都属于这种类型层面的计算。

<a id="section-2"></a>
## 2. 类型空间与值空间

TypeScript 同时存在两套空间：

```ts
interface Config {
  debug: boolean;
}

const config: Config = { debug: true };
```

- `Config` 只存在于类型空间，编译后会消失。
- `config` 存在于运行时值空间，可以被打印和传给函数。

因此不能把接口当作运行时值：

```ts
// console.log(Config); // ❌ Config 不是运行时变量
```

类比较特殊，同时拥有两套身份：类名可以作为实例类型，也可以作为运行时构造函数。理解这一点能解释很多“为什么这个类型不能用于 `instanceof`”的问题。

<a id="section-3"></a>
## 3. `typeof`：从值推导类型

<a id="subsection-3-1"></a>
### 3.1 类型位置的 `typeof`

在类型位置，`typeof` 可以取得一个已有值的类型：

```ts
const defaultConfig = {
  theme: "light",
  pageSize: 20,
  showTips: true,
};

type Config = typeof defaultConfig;
// {
//   theme: string;
//   pageSize: number;
//   showTips: boolean;
// }
```

这比重新写一遍 `Config` 更不容易和默认值不同步。

<a id="subsection-3-2"></a>
### 3.2 运行时 `typeof` 与类型位置的区别

```ts
const value = "hello";

if (typeof value === "string") {
  console.log(value.toUpperCase());
}

type ValueType = typeof value; // string
```

第一个 `typeof` 是 JavaScript 运算，会在运行时返回字符串；第二个 `typeof` 是 TypeScript 类型查询，只在编译时工作。

<a id="subsection-3-3"></a>
### 3.3 `as const` 保留字面量

普通对象的属性会被拓宽为 `string`、`number`、`boolean`：

```ts
const config = {
  theme: "light",
};

type Theme1 = typeof config.theme; // string
```

如果要保留具体值，并让整个结构只读，可以使用 `as const`：

```ts
const config = {
  theme: "light",
  pageSize: 20,
} as const;

type Theme2 = typeof config.theme; // "light"
type Config = typeof config;
// { readonly theme: "light"; readonly pageSize: 20 }
```

`as const` 只影响编译期推断，不会替代运行时的 `Object.freeze`。

<a id="subsection-3-4"></a>
### 3.4 `typeof` 推导函数和类

```ts
function createUser(name: string, age: number) {
  return { id: crypto.randomUUID(), name, age };
}

type CreateUser = typeof createUser;
// (name: string, age: number) => { id: string; name: string; age: number }

class UserService {}
type UserServiceConstructor = typeof UserService; // 构造函数一侧
type UserServiceInstance = UserService;            // 实例一侧
```

函数本身与函数返回的对象是不同类型；类的构造函数一侧和实例一侧也不同。

<a id="section-4"></a>
## 4. `satisfies`：验证结构但保留推断

假设路由必须符合统一结构：

```ts
type Route = {
  path: `/${string}`;
  auth: boolean;
};
```

`satisfies` 做的是可赋值性检查：表达式必须能赋给目标类型；检查完成后，变量仍使用表达式最终推断出的类型。这里的“保留推断”不是“自动把所有字面量都固定下来”：上下文类型、对象或数组的可变性，以及是否使用 `as const`，都会影响最终结果。

直接标注会丢失对象的具体键和值信息：

```ts
const routes: Record<string, Route> = {
  home: { path: "/", auth: false },
  profile: { path: "/profile", auth: true },
};

type RouteName1 = keyof typeof routes; // string
```

使用 `satisfies` 可以检查结构，同时保留表达式自己的类型：

```ts
const routes = {
  home: { path: "/", auth: false },
  profile: { path: "/profile", auth: true },
} satisfies Record<string, Route>;

type RouteName2 = keyof typeof routes; // "home" | "profile"
type ProfilePath = typeof routes.profile.path;
// 具体结果受 `Route.path` 的上下文类型和可变性影响，不应理解为自动 `as const`
```

如果还需要把对象和属性固定为字面量并设为只读，可以组合使用：

```ts
const literalRoutes = {
  home: { path: "/", auth: false },
  profile: { path: "/profile", auth: true },
} as const satisfies Record<string, Route>;

type LiteralProfilePath = typeof literalRoutes.profile.path; // "/profile"
```

三种写法的侧重点：

| 写法 | 检查可赋值性 | 保留的推断信息 | 是否改变表达式类型 |
| --- | --- | --- | --- |
| `const x: T = value` | 是 | 由 `T` 和上下文决定，通常不保留全部细节 | 是，变量类型是 `T` |
| `value as T` | 不可靠，属于断言 | 否 | 是，告诉编译器相信 `T` |
| `value satisfies T` | 是 | 通常保留具体键等表达式信息；字面量仍受上下文和可变性影响 | 否，保留表达式最终推断 |

配置表、路由表和权限表通常很适合使用 `satisfies`。

<a id="subsection-4-1"></a>
### 4.1 `const` 泛型参数：默认保留字面量推断

普通泛型为了允许后续修改，往往把数组和对象推断得比较宽：

```ts
function defineNames<T extends { names: readonly string[] }>(value: T): T["names"] {
  return value.names;
}

const names = defineNames({ names: ["小明", "小红"] });
// 通常是 string[]，具体字面量被拓宽
```

TypeScript 5.0 起，可以在类型参数前加 `const`，让调用处默认使用更精确的字面量推断（见官方的 [`const` 类型参数说明](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-0.html#const-type-parameters)）：

```ts
function defineNames<const T extends { names: readonly string[] }>(
  value: T,
): T["names"] {
  return value.names;
}

const names = defineNames({ names: ["小明", "小红"] });
// readonly ["小明", "小红"]
```

它特别适合封装配置、路由、命令和元组构造函数：

```ts
function tuple<const T extends readonly unknown[]>(...items: T): T {
  return items;
}

const pair = tuple("id", 1);
// readonly ["id", 1]
```

注意：

- `const` 泛型参数只改变推断策略，不会让运行时对象自动冻结。
- 它不拒绝可变值；如果约束写得过于可变，可能仍然得到拓宽类型。
- 只有调用者确实需要保留字面量时才使用，否则会让类型提示变得过于具体。

<a id="section-5"></a>
## 5. `keyof`：取得对象的键

```ts
type User = {
  id: number;
  name: string;
  active: boolean;
};

type UserKey = keyof User;
// "id" | "name" | "active"
```

<a id="subsection-5-1"></a>
### 5.1 `keyof` 与索引签名

```ts
type StringDictionary = {
  [key: string]: string;
};

type DictionaryKey = keyof StringDictionary;
// string | number
```

JavaScript 对象的数字键最终也会以字符串形式处理，所以字符串索引签名的键通常包含 `number`。

```ts
type NumberDictionary = {
  [key: number]: string;
};

type NumberKey = keyof NumberDictionary;
// number
```

对象键的完整联合类型在标准库中叫 `PropertyKey`：

```ts
// TypeScript 标准库已声明：type PropertyKey = string | number | symbol;

function readKey<T extends object, K extends PropertyKey>(
  object: T,
  key: K,
): unknown {
  return key in object
    ? (object as Record<PropertyKey, unknown>)[key]
    : undefined;
}
```

实际项目中直接使用全局 `PropertyKey` 即可，不必重复声明。需要注意，`keyof T` 可能比 `PropertyKey` 更精确；如果类型只有 `"id" | "name"` 两个键，不要把它放宽成所有字符串键。

<a id="subsection-5-2"></a>
### 5.2 数组和元组的键

```ts
type ArrayKeys = keyof string[];
// number | "length" | "push" | "pop" | ...

type Tuple = [string, number];
type TupleKeys = keyof Tuple;
```

数组的 `keyof` 不只是数字，还包括 `length` 和数组方法。若只想取得元组的位置键，需要额外过滤 `keyof` 的结果。

<a id="subsection-5-3"></a>
### 5.3 联合类型和交叉类型的键

这是 `keyof` 最容易被忽略、却非常重要的行为：

```ts
type Person = { name: string; age: number };
type Employee = { name: string; department: string };

type UnionKeys = keyof (Person | Employee);
// "name"：联合值无论是哪一种，都能安全访问的键

type IntersectionKeys = keyof (Person & Employee);
// "name" | "age" | "department"：交叉值必须拥有两边的全部键
```

可以这样理解：

- `keyof (A | B)` 只能得到两者的公共键，因为运行时拿到联合值时无法确定它拥有哪一侧的专属键。
- `keyof (A & B)` 可以得到两者的全部键，因为交叉值必须同时具备两侧结构。

如果需要取得联合所有成员的键，而不是公共键，可以利用分布式条件类型：

```ts
type AllKeys<T> = T extends unknown ? keyof T : never;
type EveryKey = AllKeys<Person | Employee>;
// "name" | "age" | "department"
```

下面的函数只能安全读取公共键：

```ts
function getCommon<T, K extends keyof T>(value: T, key: K): T[K] {
  return value[key];
}

declare const value: Person | Employee;
getCommon(value, "name");
// getCommon(value, "age"); // ❌ age 不是联合类型的公共键
```

若要读取专属字段，应先通过可辨识字段或 `in` 进行类型收窄，而不是用断言绕过 `keyof` 的限制。

<a id="section-6"></a>
## 6. 交叉类型与 `&` 操作符

TypeScript 中的 `&` 有两种完全不同的使用位置：

1. 出现在类型位置时，表示交叉类型。
2. 出现在值表达式中时，表示 JavaScript 的按位与运算。

<a id="subsection-6-1"></a>
### 6.1 交叉类型的基本含义

`A & B` 表示一个值必须同时满足类型 `A` 和类型 `B`：

```ts
type User = {
  id: number;
  name: string;
};

type Timestamp = {
  createdAt: Date;
  updatedAt: Date;
};

type UserWithTimestamp = User & Timestamp;

const user: UserWithTimestamp = {
  id: 1,
  name: "小明",
  createdAt: new Date(),
  updatedAt: new Date(),
};
```

`UserWithTimestamp` 必须拥有两个类型中的全部属性。可以把 `&` 读成“并且”，而不是运行时的对象拼接。

<a id="subsection-6-2"></a>
### 6.2 `&` 与 `|` 的区别

```ts
type A = { name: string };
type B = { age: number };

type Union = A | B;
type Intersection = A & B;
```

- `A | B`：满足 `A` 或 `B`，表示多种可能。
- `A & B`：同时满足 `A` 和 `B`，表示能力或约束的组合。

```ts
const union1: Union = { name: "小明" };
const union2: Union = { age: 18 };

const intersection: Intersection = {
  name: "小明",
  age: 18,
};
```

<a id="subsection-6-3"></a>
### 6.3 组合可复用能力

交叉类型经常用于组合多个独立能力：

```ts
type Identifiable = {
  id: number;
};

type Serializable = {
  serialize(): string;
};

type Entity = Identifiable & Serializable;

const entity: Entity = {
  id: 1,
  serialize() {
    return JSON.stringify({ id: this.id });
  },
};
```

它也适合描述泛型函数增强后的返回值：

```ts
function withTimestamp<T extends object>(
  value: T,
): T & { createdAt: Date } {
  return {
    ...value,
    createdAt: new Date(),
  };
}

const userWithTime = withTimestamp({ id: 1, name: "小明" });

userWithTime.name;      // 原对象的属性仍然存在
userWithTime.createdAt; // 同时拥有新增属性
```

<a id="subsection-6-4"></a>
### 6.4 同名属性与 `never`

两个类型有同名属性时，该属性必须同时满足两边的类型：

```ts
type StringValue = {
  value: string;
};

type StringOrNumberValue = {
  value: string | number;
};

type Compatible = StringValue & StringOrNumberValue;
// Compatible["value"] 是 string
```

`string` 同时满足 `string` 和 `string | number`，因此结果是 `string`。

如果属性完全冲突，交叉结果会变成 `never`：

```ts
type NumberValue = {
  value: number;
};

type Impossible = StringValue & NumberValue;
// Impossible["value"] 是 string & number，即 never
```

不存在同时是 `string` 和 `number` 的值，所以无法正常构造 `Impossible`。这是交叉类型最常见的陷阱之一：不要用 `&` 强行合并互相冲突的业务模型。

<a id="subsection-6-5"></a>
### 6.5 原始类型和字面量的交叉

```ts
type Admin = string & "admin";
// "admin"
```

`"admin"` 本来就是 `string` 的子类型，因此交叉结果是更具体的 `"admin"`。

完全不相容的类型会得到 `never`：

```ts
type ImpossibleValue = string & number;
// never

type ImpossibleStatus = "success" & "error";
// never
```

<a id="subsection-6-6"></a>
### 6.6 交叉类型和联合类型组合

```ts
type WithId = { id: number };
type Named = { name: string };
type Titled = { title: string };

type Result = WithId & (Named | Titled);
```

可以把它理解为：

```ts
type Result =
  | (WithId & Named)
  | (WithId & Titled);
```

因此下面两个值都合法：

```ts
const namedResult: Result = {
  id: 1,
  name: "小明",
};

const titledResult: Result = {
  id: 2,
  title: "TypeScript 入门",
};
```

联合和交叉混用时，建议使用括号明确关系。若业务上是有限的状态分支，优先使用带 `kind`/`status` 的可辨识联合。

<a id="subsection-6-7"></a>
### 6.7 函数类型的交叉

函数类型也能进行交叉，效果类似函数重载：

```ts
type Formatter =
  & ((value: string) => string)
  & ((value: number) => number);

declare const format: Formatter;

const text = format(" hello "); // string
const count = format(1.5);      // number
```

不过，实现交叉函数经常需要类型断言。需要编写实际函数时，函数重载通常更清晰：

```ts
function format(value: string): string;
function format(value: number): number;
function format(value: string | number): string | number {
  return typeof value === "string"
    ? value.trim()
    : Math.round(value);
}
```

<a id="subsection-6-8"></a>
### 6.8 `&` 与 `interface extends`

下面两种写法都能扩展对象结构：

```ts
interface BaseUser {
  id: number;
}

interface AdminUser extends BaseUser {
  permissions: string[];
}
```

```ts
type BaseUser = {
  id: number;
};

type AdminUser = BaseUser & {
  permissions: string[];
};
```

选择建议：

- 清晰、稳定的对象继承关系可优先使用 `interface extends`。
- 临时组合类型、泛型结果和类型运算适合使用 `&`。
- `&` 还能组合联合类型、原始类型和函数类型，适用范围更广。
- 属性冲突时，接口继承一般会直接报错，而交叉类型可能产生 `never`。

<a id="subsection-6-9"></a>
### 6.9 交叉类型不会在运行时合并对象

交叉类型只存在于编译阶段：

```ts
type Basic = { name: string };
type Detail = { age: number };
type Combined = Basic & Detail;
```

上面的类型声明不会创建或合并任何对象。真正的运行时合并需要使用对象展开或 `Object.assign`：

```ts
const basic = { name: "小明" };
const detail = { age: 18 };

const combined = {
  ...basic,
  ...detail,
};
```

两者有一个重要差别：运行时对象展开遇到同名属性时，后面的值会覆盖前面的值；交叉类型则要求同名属性的类型同时成立。

<a id="subsection-6-10"></a>
### 6.10 值表达式中的按位与

当 `&` 出现在运行时代码中时，它是 JavaScript 的按位与：

```ts
const result = 6 & 3;
```

计算过程：

```text
6 = 110
3 = 011
&   010
```

结果是 `2`。按位与常用于检查位标志：

```ts
const READ = 1;   // 001
const WRITE = 2;  // 010
const DELETE = 4; // 100

const permission = READ | WRITE; // 011

if ((permission & WRITE) !== 0) {
  console.log("拥有写权限");
}
```

这里的 `&` 会参与真实计算，与类型位置的交叉类型没有关系。

<a id="subsection-6-11"></a>
### 6.11 使用建议

- 把 `A & B` 理解为“同时满足”，而不是简单覆盖字段。
- 注意同名属性冲突，它们可能导致 `never`。
- 不要把类型交叉误认为运行时对象合并。
- 复杂对象继承优先考虑可读性更好的 `interface extends`。
- 联合类型和交叉类型混用时使用括号明确关系。
- 高级类型应该减少重复、帮助调用者，而不是单纯追求复杂技巧。

<a id="section-7"></a>
## 7. 索引访问类型：`T[K]`

`T[K]` 表示“从类型 `T` 中取出键 `K` 对应的属性类型”：

```ts
type User = {
  id: number;
  name: string;
  active: boolean;
};

type UserName = User["name"]; // string
type UserIdOrName = User["id" | "name"]; // number | string
type UserValue = User[keyof User]; // number | string | boolean
```

键本身也可以是泛型，但必须保证它确实是 `T` 的键：

```ts
function getProperty<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}

const user = { id: 1, name: "小明", active: true };

const name = getProperty(user, "name"); // string
const active = getProperty(user, "active"); // boolean
// getProperty(user, "email"); // ❌ email 不是 user 的键
```

`K extends keyof T` 保证键合法，`T[K]` 让返回值随具体键变化。这是 TypeScript 中非常重要的“输入和输出建立关系”的模式。

<a id="subsection-7-1"></a>
### 7.1 使用 `number` 取得数组元素类型

数组可以使用数字下标访问，因此 `T[number]` 表示“取得 `T` 中所有数字下标对应的元素类型”：

```ts
type User = {
  id: number;
  name: string;
};

type Users = User[];
type UserElement = Users[number];
// User

type ReadonlyUsers = readonly User[];
type ReadonlyUserElement = ReadonlyUsers[number];
// User
```

对于普通数组，`number` 不是某一个具体下标，而是“任意数字下标”：

```ts
type Mixed = (string | number)[];
type MixedElement = Mixed[number];
// string | number
```

这也是从数组类型提取元素类型的常用写法：

```ts
type ElementOf<T extends readonly unknown[]> = T[number];

type Name = ElementOf<string[]>;          // string
type Id = ElementOf<readonly number[]>;   // number
type Value = ElementOf<Array<boolean>>;  // boolean
```

<a id="subsection-7-2"></a>
### 7.2 从数组值推导元素联合类型

配合类型位置的 `typeof`，可以从一个数组值推导元素类型：

```ts
const roles = ["admin", "editor", "viewer"] as const;

type Role = (typeof roles)[number];
// "admin" | "editor" | "viewer"
```

这里分成两步：

1. `typeof roles` 取得值 `roles` 的类型。
2. `[number]` 取得这个只读元组中任意位置的元素类型。

如果没有 `as const`，数组元素会被拓宽为普通 `string`：

```ts
const looseRoles = ["admin", "editor", "viewer"];
type LooseRole = (typeof looseRoles)[number];
// string
```

所以“固定选项数组”常写成 `as const`，而“运行时会增删的普通数组”通常保留 `string[]`。

<a id="subsection-7-3"></a>
### 7.3 `number` 与元组

元组的长度和每个位置类型是已知的：

```ts
type Coordinate = [number, number];
type CoordinateElement = Coordinate[number];
// number

type Record = [id: number, name: string, active: boolean];
type RecordElement = Record[number];
// number | string | boolean
```

`Tuple[number]` 会得到所有位置类型的联合，而不是某个位置的类型。若要取得具体位置，应使用具体数字字面量：

```ts
type Id = Record[0];      // number
type Name = Record[1];    // string
type Active = Record[2];  // boolean
```

使用普通 `number` 下标时，TypeScript 必须考虑所有可能的位置，因此结果只能是联合类型：

```ts
declare const record: Record;
const value = record[Math.random() > 0.5 ? 0 : 1];
// number | string
```

<a id="subsection-7-4"></a>
### 7.4 `T[number]` 与运行时越界

`T[number]` 描述的是数组元素的静态类型，不表示数组运行时一定有元素：

```ts
type Names = string[];
type NameElement = Names[number]; // string

const names: Names = [];
const first = names[0];
// 开启 noUncheckedIndexedAccess 后：string | undefined
```

要区分两件事：

- `Names[number]`：类型层面“数组元素是什么类型”。
- `names[0]`：运行时读取某个位置，可能因为越界得到 `undefined`。

因此 `T[number]` 不会替代空数组判断，也不会消除 `noUncheckedIndexedAccess` 带来的安全提示。

<a id="subsection-7-5"></a>
### 7.5 对象数字索引签名

`number` 不只可以索引数组，也可以索引数字键对象：

```ts
type ScoreMap = {
  [id: number]: number;
};

type Score = ScoreMap[number];
// number
```

如果对象有明确的键，优先使用键名或 `keyof`，不要为了方便把所有对象写成数字索引签名，否则会丢失键集合信息。

<a id="section-8"></a>
## 8. 映射类型：遍历并变换属性

<a id="subsection-8-1"></a>
### 8.1 基本语法

```ts
type Optional<T> = {
  [K in keyof T]?: T[K];
};

type User = {
  id: number;
  name: string;
};

type OptionalUser = Optional<User>;
// { id?: number; name?: string }
```

可以把它读成：“遍历 `T` 的每个键 `K`，生成一个同名属性，类型为 `T[K]`。”

<a id="subsection-8-2"></a>
### 8.2 添加和移除修饰符

```ts
type ReadonlyRequired<T> = {
  readonly [K in keyof T]-?: T[K];
};

type MutableOptional<T> = {
  -readonly [K in keyof T]?: T[K];
};
```

- `readonly` 添加只读。
- `-readonly` 移除只读。
- `?` 添加可选。
- `-?` 移除可选。

<a id="subsection-8-3"></a>
### 8.3 根据属性值筛选键

先构造每个键的中间结果，再取联合类型：

```ts
type StringKeys<T> = {
  [K in keyof T]-?: T[K] extends string ? K : never;
}[keyof T];

type User = {
  id: number;
  name: string;
  email: string;
  active: boolean;
};

type UserStringKey = StringKeys<User>;
// "name" | "email"
```

过程可以展开为：

```ts
type UserStringKeyTable = {
  id: never;
  name: "name";
  email: "email";
  active: never;
};

type UserStringKey = UserStringKeyTable[keyof User];
// never | "name" | "email" | never，最终是 "name" | "email"
```

`never` 在联合类型中会被消除，因此常被用来过滤成员。

<a id="subsection-8-4"></a>
### 8.4 键重映射

映射类型中的 `as` 可以改变属性名：

```ts
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type User = {
  id: number;
  name: string;
};

type UserGetters = Getters<User>;
// {
//   getId: () => number;
//   getName: () => string;
// }
```

`string & K` 的作用是把 `K` 限制为字符串键，因为 `keyof T` 也可能包含 `number` 或 `symbol`。

通过映射为 `never`，可以删除属性：

```ts
type WithoutId<T> = {
  [K in keyof T as K extends "id" ? never : K]: T[K];
};

type PublicUser = WithoutId<User>;
// { name: string }
```

<a id="subsection-8-5"></a>
### 8.5 同态映射类型与非同态映射类型

直接使用 `[K in keyof T]` 的映射类型叫同态映射类型。它会基于原类型逐属性变换，并默认保留原属性的 `readonly` 和可选修饰符：

```ts
type Source = {
  readonly id: number;
  name?: string;
};

type Boxed<T> = {
  [K in keyof T]: { value: T[K] };
};

type Result = Boxed<Source>;
// {
//   readonly id: { value: number };
//   name?: { value: string };
// }
```

如果键集合是独立给出的，或者通过 `as` 改写/过滤了键，就不再是简单的同态复制：

```ts
type Flags<T> = {
  [K in keyof T as `has${Capitalize<string & K>}`]: boolean;
};
```

这类映射仍然很有用，但不能假定所有原修饰符和联合分布行为都与 `Partial<T>` 完全相同。写自定义工具时，应明确测试可选属性、只读属性和联合输入。

<a id="subsection-8-6"></a>
### 8.6 映射类型处理联合成员

```ts
type A = { kind: "a"; value: string };
type B = { kind: "b"; value: number };

type ReadonlyState = Readonly<A | B>;
```

对同态映射而言，TypeScript 通常会保留联合成员的结构，使 `kind` 仍可用于收窄。不要把一个联合整体先转换成普通索引签名，否则可能丢失可辨识联合的信息。

<a id="section-9"></a>
## 9. 条件类型：类型层面的 `if`

<a id="subsection-9-1"></a>
### 9.1 基本形式

```ts
type IsString<T> = T extends string ? true : false;

type A = IsString<"hello">; // true
type B = IsString<number>;   // false
```

`T extends U` 这里不是类继承，而是判断 `T` 是否可以赋值给 `U`。条件类型可以嵌套，但过深会影响可读性和编译速度。

<a id="subsection-9-2"></a>
### 9.2 条件类型中的约束

```ts
type MessageOf<T> = T extends { message: unknown }
  ? T["message"]
  : never;

type EmailMessage = MessageOf<{ message: string; code: number }>;
// string

type NoMessage = MessageOf<{ code: number }>;
// never
```

这比直接写 `T["message"]` 更安全，因为后者要求所有传入类型都拥有 `message`。

<a id="subsection-9-3"></a>
### 9.3 `never` 的作用

```ts
type ToArray<T> = T extends unknown ? T[] : never;
```

`never` 是空类型，表示不存在任何值。它在联合类型中会被删除：

```ts
type Result = string | never; // string
```

所以 `never` 很适合表示“不符合条件的成员”，也适合做穷尽性检查。

<a id="section-10"></a>
## 10. 分布式条件类型

当条件类型的左侧是裸类型参数时，传入联合类型会逐个计算：

```ts
type ToArray<T> = T extends unknown ? T[] : never;

type Result = ToArray<string | number>;
// ToArray<string> | ToArray<number>
// string[] | number[]
```

这叫分布式条件类型。它特别适合筛选联合成员：

```ts
type OnlyString<T> = T extends string ? T : never;
type Strings = OnlyString<string | number | boolean>;
// string
```

<a id="subsection-10-1"></a>
### 10.1 关闭分布

如果想把整个联合当成一个整体，使用元组包裹两边：

```ts
type ToArrayTogether<T> = [T] extends [unknown] ? T[] : never;

type Result = ToArrayTogether<string | number>;
// (string | number)[]
```

`[T] extends [U]` 与 `T extends U` 的区别，通常就是“整体判断”与“逐个判断”。

<a id="section-11"></a>
## 11. `infer`：在条件类型中提取类型

`infer` 可以在条件成立时声明一个待推断的类型变量。

<a id="subsection-11-1"></a>
### 11.1 提取数组元素

```ts
type ElementOf<T> = T extends readonly (infer Element)[]
  ? Element
  : never;

type Element = ElementOf<readonly User[]>; // User
type NoElement = ElementOf<string>;        // never
```

<a id="subsection-11-2"></a>
### 11.2 提取 Promise 结果

```ts
type UnwrapPromise<T> = T extends Promise<infer Value> ? Value : T;

type Name = UnwrapPromise<Promise<string>>; // string
type Count = UnwrapPromise<number>;         // number
```

标准库提供了更完整的 `Awaited<T>`，可以处理嵌套 Promise 和 thenable：

```ts
type Data = Awaited<Promise<Promise<User[]>>>; // User[]
```

<a id="subsection-11-3"></a>
### 11.3 提取函数参数和返回值

```ts
type Return<T> = T extends (...args: never[]) => infer Result
  ? Result
  : never;

type ParametersOf<T> = T extends (...args: infer Args) => unknown
  ? Args
  : never;

type Fn = (id: number, verbose?: boolean) => Promise<User>;

type FnResult = Return<Fn>;      // Promise<User>
type FnArgs = ParametersOf<Fn>; // [id: number, verbose?: boolean]
```

实际项目中通常直接使用标准工具类型：

```ts
type FnResult = ReturnType<Fn>;
type FnArgs = Parameters<Fn>;
```

<a id="subsection-11-4"></a>
### 11.4 重载函数的推断限制

一个函数可以有多个调用签名，但 `ReturnType` 和 `Parameters` 只从对外重载列表中的最后一个重载签名推断：它们不会读取实现签名，也不会根据调用时的参数重新选择重载。

```ts
function parse(value: string): number;
function parse(value: number): string;
function parse(value: string | number): string | number {
  return typeof value === "string" ? Number(value) : String(value);
}

type Parsed = ReturnType<typeof parse>;
// string（最后一个重载签名的返回类型）
type ParsedArgs = Parameters<typeof parse>;
// [value: number]（最后一个重载签名的参数）
```

如果希望类型工具精确区分每一种输入，通常应使用可辨识联合或定义一个“输入到输出”的映射，而不是期待 `ReturnType` 自动保留重载关系：

```ts
interface ParseMap {
  text: number;
  count: string;
}

type ParseResult<K extends keyof ParseMap> = ParseMap[K];
```

<a id="subsection-11-5"></a>
### 11.5 泛型实例化表达式

如果想把一个泛型函数固定成某个类型，可以在表达式后直接写类型参数，不必再包一层函数：

```ts
function createBox<T>(value: T): { value: T } {
  return { value };
}

const createStringBox = createBox<string>;
const box = createStringBox("hello");
// { value: string }

// createStringBox(123); // ❌ 参数必须是 string
```

这叫泛型实例化表达式，适合把通用函数作为依赖传递给只需要某一种类型的模块：

```ts
function mapValue<T, U>(value: T, map: (value: T) => U): U {
  return map(value);
}

const mapNumber = mapValue<number, string>;
const text = mapNumber(42, String); // string
```

它只是生成一个更具体的函数类型，不会在运行时创建新的包装函数。类型参数的数量和约束必须符合原函数定义。

<a id="section-12"></a>
## 12. 常用内置工具类型及其原理

本节展示最常用工具的核心原理。完整的内置类型清单、`NoInfer`、`ThisType`、字符串内置类型以及更完整的组合案例，见补充文档[《内置工具类型与实现原理》](12-内置工具类型与实现原理.md)。

<a id="subsection-12-1"></a>
### 12.1 属性变换工具

```ts
type User = {
  readonly id: number;
  name: string;
  email?: string;
};

type UserPatch = Partial<User>;
type CompleteUser = Required<User>;
type FrozenUser = Readonly<User>;
type UserPreview = Pick<User, "id" | "name">;
type UserWithoutId = Omit<User, "id">;
```

它们大致可以这样实现：

```ts
type MyPartial<T> = {
  [K in keyof T]?: T[K];
};

type MyRequired<T> = {
  [K in keyof T]-?: T[K];
};

type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};

type MyPick<T, K extends keyof T> = {
  [P in K]: T[P];
};

type MyOmit<T, K extends keyof T> = MyPick<T, Exclude<keyof T, K>>;
```

<a id="subsection-12-2"></a>
### 12.2 联合和键工具

```ts
type Role = "admin" | "editor" | "viewer";

type EditableRole = Exclude<Role, "viewer">;
// "admin" | "editor"

type AdminOrViewer = Extract<Role, "admin" | "viewer">;
// "admin" | "viewer"

type MaybeName = string | null | undefined;
type Name = NonNullable<MaybeName>;
// string
```

它们的本质就是条件类型：

```ts
type MyExclude<T, U> = T extends U ? never : T;
type MyExtract<T, U> = T extends U ? T : never;
type MyNonNullable<T> = T extends null | undefined ? never : T;
```

<a id="subsection-12-3"></a>
### 12.3 对象映射和函数工具

```ts
type UserById = Record<number, User>;

function createUser(name: string, age: number) {
  return { id: crypto.randomUUID(), name, age };
}

type CreateUserArgs = Parameters<typeof createUser>;
type CreatedUser = ReturnType<typeof createUser>;
```

`Record<K, V>` 可理解为：键是 `K`，每个键的值是 `V`：

```ts
type MyRecord<K extends PropertyKey, V> = {
  [P in K]: V;
};
```

其他常用工具：

```ts
type Constructor<T = object> = abstract new (...args: any[]) => T;

type UserInstance = InstanceType<typeof UserService>;
type UserConstructorArgs = ConstructorParameters<typeof UserService>;
```

尽量不要为了“自己实现一遍”而在业务代码中替代标准工具类型；理解原理后，实际使用标准名称可降低团队沟通成本。

<a id="section-13"></a>
## 13. 递归类型

映射类型可以引用自身，构造递归类型。

<a id="subsection-13-1"></a>
### 13.1 深层只读

```ts
type DeepReadonly<T> =
  T extends (...args: never[]) => unknown
    ? T
    : T extends readonly unknown[]
      ? Readonly<{ [K in keyof T]: DeepReadonly<T[K]> }>
      : T extends object
        ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
        : T;

type Settings = {
  theme: string;
  editor: {
    fontSize: number;
    plugins: string[];
  };
};

type FrozenSettings = DeepReadonly<Settings>;
```

函数被单独保留，是因为函数也是对象；如果直接递归到所有 `object`，可能把函数的调用签名破坏掉。

<a id="subsection-13-2"></a>
### 13.2 深层可选

```ts
type DeepPartial<T> =
  T extends (...args: never[]) => unknown
    ? T
    : T extends readonly unknown[]
      ? { [K in keyof T]?: DeepPartial<T[K]> }
      : T extends object
        ? { [K in keyof T]?: DeepPartial<T[K]> }
        : T;
```

函数也是对象；如果没有第一个分支，映射 `keyof` 会破坏函数的调用签名。保留函数后，函数属性仍可被设为可选，但一旦存在，参数和返回值仍保持原样：

```ts
type EditorConfig = {
  onSave: (value: string) => void;
  createdAt: Date;
};

type PartialEditorConfig = DeepPartial<EditorConfig>;
// {
//   onSave?: (value: string) => void;
//   createdAt?: { /* Date 的成员仍会被学习版递归映射 */ };
// }
```

`Date`、`Map`、`Set` 等特殊对象仍会进入后面的 `T extends object` 分支；这里没有为它们保留原子类型，因此这只是学习版边界。生产工具通常要为这些类型、数组和元组分别定义策略，并在 `exactOptionalPropertyTypes` 下明确是否允许显式 `undefined`。

<a id="subsection-13-3"></a>
### 13.3 JSON 可表示的值

```ts
type JsonPrimitive = string | number | boolean | null;

type JsonValue =
  | JsonPrimitive
  | JsonValue[]
  | { [key: string]: JsonValue };

function stringify(value: JsonValue): string {
  return JSON.stringify(value);
}

stringify({ user: { id: 1 }, tags: ["ts"] });
// stringify({ createdAt: new Date() }); // ❌ Date 不在 JsonValue 中
```

递归类型适合表达树、嵌套配置、JSON 和文件目录；递归过深会造成编译器达到实例化深度限制。

<a id="section-14"></a>
## 14. 模板字面量类型

<a id="subsection-14-1"></a>
### 14.1 生成固定格式的字符串

```ts
type EventName = "click" | "focus" | "submit";
type HandlerName = `on${Capitalize<EventName>}`;
// "onClick" | "onFocus" | "onSubmit"
```

内置字符串工具还包括 `Uppercase`、`Lowercase`、`Uncapitalize`：

```ts
type Header = Uppercase<"content-type">; // "CONTENT-TYPE"
type Field = Uncapitalize<"Name">;       // "name"
```

<a id="subsection-14-2"></a>
### 14.2 类型安全的事件表

```ts
type Payloads = {
  save: { id: number };
  cancel: undefined;
};

type EventHandlers<T> = {
  [K in keyof T as `on${Capitalize<string & K>}`]:
    T[K] extends undefined
      ? () => void
      : (payload: T[K]) => void;
};

type Handlers = EventHandlers<Payloads>;
// {
//   onSave: (payload: { id: number }) => void;
//   onCancel: () => void;
// }
```

<a id="subsection-14-3"></a>
### 14.3 从路径提取参数

条件类型和模板字面量可以递归解析路径：

```ts
type PathParams<Path extends string> =
  Path extends `${string}:${infer Param}/${infer Rest}`
    ? { [K in Param | keyof PathParams<`/${Rest}`>]: string }
    : Path extends `${string}:${infer Param}`
      ? { [K in Param]: string }
      : Record<never, never>;

type Params = PathParams<"/users/:userId/posts/:postId">;
// { userId: string; postId: string }
```

这种类型可以让路由函数要求正确的参数：

```ts
declare function route<Path extends string>(
  path: Path,
  params: PathParams<Path>,
): string;

route("/users/:userId", { userId: "1" });
// route("/users/:userId", {}); // ❌ 缺少 userId
```

这里使用 `Record<never, never>` 只是让无参数分支的 `keyof` 为 `never`，避免把 `{}` 误解为“精确空对象”；TypeScript 的结构类型系统并没有一个能在所有情况下阻止多余键的普通 `{}` 类型。这个学习版解析器只处理形如 `:name` 的必填路径段，不处理可选参数、重复参数、查询字符串或 URL 编码；例如带 `?` 或查询串的路径不能据此获得可靠保证。生产环境应交给路由器解析，并对外部参数做运行时校验和编码。

<a id="section-15"></a>
## 15. 实际案例：从字段配置推导表单类型

先用一个键到值类型的映射作为字段 `kind` 的唯一来源，再由它生成字段联合：

```ts
type FieldKindMap = {
  text: string;
  number: number;
  checkbox: boolean;
};

type FieldKind = keyof FieldKindMap;

type Field = {
  [K in FieldKind]: {
    kind: K;
    required: boolean;
  };
}[FieldKind];

const formSchema = {
  name: { kind: "text", required: true },
  age: { kind: "number", required: false },
  subscribed: { kind: "checkbox", required: true },
} as const satisfies Record<string, Field>;
```

输入中的 `as const` 保留了每个字段的 `kind`、`required: true` 或 `required: false`；`satisfies` 则检查配置仍符合 `Field`，但不把这些具体信息抹平。接着用映射索引取得字段值类型：

```ts
type FieldValue<F extends Field> = FieldKindMap[F["kind"]];
```

最后遍历 schema，并按 `required` 的字面量把键分成必填和可选两组：

```ts
type FormValues<Schema extends Record<string, Field>> = {
  [K in keyof Schema as Schema[K]["required"] extends true ? K : never]-?:
    FieldValue<Schema[K]>;
} & {
  [K in keyof Schema as Schema[K]["required"] extends true ? never : K]?:
    FieldValue<Schema[K]>;
};

type Values = FormValues<typeof formSchema>;
// {
//   name: string;
//   subscribed: boolean;
//   age?: number;
// }

const validValues: Values = {
  name: "小明",
  subscribed: true,
};

const validValuesWithAge: Values = {
  name: "小明",
  subscribed: false,
  age: 18,
};

// const missingRequired: Values = { name: "小明" };
// ❌ 缺少 required: true 的 subscribed
// const explicitUndefined: Values = {
//   name: "小明",
//   subscribed: true,
//   age: undefined,
// };
// ❌ exactOptionalPropertyTypes 下，可选键不等于显式允许 undefined
```

数据流是“配置输入 → 保留字面量 → `FieldKindMap` 生成 `Field` 联合 → `FieldValue` 按 `kind` 查值类型 → `FormValues` 按 `required` 重映射键 → 表单值输出”。如果新增 `date: Date`，只需把它加入 `FieldKindMap`，`Field` 和 `FormValues` 就会自然传播出 `kind: "date"` 与 `Date`；这属于映射关系的传播，不是声称编译器会对所有运行时分支做穷尽检查。

这里采用“明确 `true` 才必填”的保守规则：如果 schema 没有用 `as const` 保留 `required` 字面量，导致它变成宽泛的 `boolean`，字段不会从结果中消失，而会落入可选键；需要强制必填时，应在配置边界保留 `true`。

<a id="section-16"></a>
## 16. `any`、`unknown`、`never` 对类型工具的影响

<a id="subsection-16-unknown"></a>
### `unknown` 是安全的顶类型

```ts
type A = string & unknown; // string
type B = string | unknown; // unknown
```

和任意类型交叉时，`unknown` 通常保留原类型；和任意类型联合时，结果变成 `unknown`。使用 `unknown` 的值前必须收窄。

<a id="subsection-16-never"></a>
### `never` 是底类型

```ts
type A = string | never; // string
type B = string & never; // never
```

它没有可构造的值，但在条件类型中非常有用。

<a id="subsection-16-any"></a>
### `any` 会破坏计算

```ts
type Message<T> = T extends string ? "text" : "other";

type WithAny = Message<any>;         // "text" | "other"
type WithUnknown = Message<unknown>; // "other"
```

`any` 可能让条件类型同时得到两个分支，因此应尽量在类型工具入口阻止 `any` 扩散。

<a id="section-17"></a>
## 17. 高级类型的常见陷阱

<a id="subsection-17-1"></a>
### 17.1 `Object`、`object` 和 `{}` 不一样

```ts
type A = object; // 非原始值，如对象、数组、函数
type B = {};     // 几乎所有非 null/undefined 的值都能赋给它
```

泛型约束若表示“必须是对象”，通常使用 `T extends object`，不要误用 `{}`。

<a id="subsection-17-2"></a>
### 17.2 工具类型通常是浅层的

```ts
type State = {
  user: { name: string };
};

type PartialState = Partial<State>;
// user 可以缺少，但一旦存在，name 仍然是必填
```

需要深层效果时才使用 `DeepPartial`，并确认它对数组和特殊对象的行为。

<a id="subsection-17-3"></a>
### 17.3 过度使用类型魔法

如果一个类型：

- 错误提示几乎无法阅读；
- 让编辑器明显变慢；
- 需要大量断言才能使用；
- 比重复写一个清晰接口更难理解；

就应该拆分类型或使用显式模型。类型系统服务于业务代码，而不是反过来。

<a id="subsection-17-4"></a>
### 17.4 品牌类型：在结构类型上增加领域身份

TypeScript 默认是结构类型系统。两个类型只要结构相同，就可能互相赋值：

```ts
type UserId = string;
type OrderId = string;

declare const userId: UserId;
const orderId: OrderId = userId; // 合法，但业务上可能是错误的
```

品牌类型通过交叉类型添加一个不会实际使用的标记，使不同领域的值不能混用：

```ts
declare const UserIdBrand: unique symbol;
declare const OrderIdBrand: unique symbol;

type UserId = string & { readonly [UserIdBrand]: "UserId" };
type OrderId = string & { readonly [OrderIdBrand]: "OrderId" };

function toUserId(value: string): UserId {
  if (!/^user_/.test(value)) throw new Error("无效的用户编号");
  return value as UserId;
}

declare const userId: UserId;
// const orderId: OrderId = userId; // ❌ 两种品牌不同
```

品牌类型只改变编译期可赋值关系，不能替代 `toUserId` 中的运行时校验。构造函数应是领域边界上唯一的断言入口，并尽量隐藏品牌字段的声明。

<a id="subsection-17-5"></a>
### 17.5 为自定义工具编写类型测试

类型工具没有运行时值，普通单元测试无法直接验证。可以用“类型相等”和 `@ts-expect-error` 做编译期测试：

```ts
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2)
    ? true
    : false;

type Expect<T extends true> = T;

type ElementOf<T extends readonly unknown[]> = T[number];

type TestElement = Expect<
  Equal<ElementOf<readonly string[]>, string>
>;

type TestRole = Expect<
  Equal<Exclude<"admin" | "viewer", "viewer">, "admin">
>;
```

测试一个应该失败的调用：

```ts
function getFirst<T>(items: readonly T[]): T | undefined {
  return items[0];
}

getFirst([1, 2, 3]);
// @ts-expect-error 字符串数组不能传给 number[]
getFirst<number>(["wrong"]);
```

`@ts-expect-error` 要求下一行确实存在错误；如果将来错误消失，TypeScript 会反过来提示这个注释多余。建议在 CI 中运行 `tsc --noEmit`，让类型测试和业务类型检查一起执行。

<a id="section-18"></a>
## 18. 泛型类型参数的方差

方差描述“泛型容器之间能否随着内部类型的继承关系进行赋值”。它是理解函数类型、事件回调和库设计的重要基础。

先定义一个父子类型关系：

```ts
interface Animal {
  name: string;
}

interface Dog extends Animal {
  bark(): void;
}
```

<a id="subsection-18-1"></a>
### 18.1 协变：只产生 `T`

```ts
interface Producer<T> {
  get: () => T;
}

declare const dogProducer: Producer<Dog>;
const animalProducer: Producer<Animal> = dogProducer;
```

`Producer<Dog>` 可以赋给 `Producer<Animal>`，因为从中取出的 `Dog` 至少是一个 `Animal`。输出位置的类型参数通常表现为协变。

<a id="subsection-18-2"></a>
### 18.2 逆变：只消费 `T`

```ts
interface Consumer<T> {
  set: (value: T) => void;
}

declare const animalConsumer: Consumer<Animal>;
const dogConsumer: Consumer<Dog> = animalConsumer;
```

一个能处理任意 `Animal` 的函数，当然也能处理 `Dog`，所以赋值方向与继承方向相反，这叫逆变。开启 `strictFunctionTypes` 后，函数参数的位置会进行更严格的逆变检查。

<a id="subsection-18-3"></a>
### 18.3 同时读写通常是不变的

```ts
interface ProducerConsumer<T> {
  get: () => T;
  set: (value: T) => void;
}
```

它既产生又消费 `T`。`ProducerConsumer<Dog>` 和 `ProducerConsumer<Animal>` 通常不能安全地互相替换，这叫不变。否则调用者可能把一只并非 `Dog` 的动物写入只接受 `Dog` 的容器。

<a id="subsection-18-4"></a>
### 18.4 `in`、`out` 方差标注

TypeScript 会根据结构自动推断大多数泛型参数的方差。库作者在极少数复杂、递归的类型中可以显式标注：

```ts
interface Producer<out T> {
  get: () => T;
}

interface Consumer<in T> {
  set: (value: T) => void;
}

interface ProducerConsumer<in out T> {
  get: () => T;
  set: (value: T) => void;
}
```

标注必须与类型的真实结构行为一致。它不能把一个实际会产生 `T` 的类型强行变成逆变，也不会改变匿名对象之间的结构比较。普通业务代码几乎不需要手写方差标注；错误标注反而可能制造不可靠的类型结果。

## 19. 实战选择指南

| 需求 | 首选工具 |
| --- | --- |
| 从配置值生成类型 | `typeof`、`as const`、`satisfies` |
| 限制对象键 | `keyof`、`K extends keyof T` |
| 取得属性值类型 | `T[K]` |
| 给每个属性统一加修饰符 | 映射类型 |
| 按条件筛选联合成员 | 条件类型、`Extract`、`Exclude` |
| 从函数/Promise/数组中取内部类型 | `infer`、`ReturnType`、`Awaited` |
| 生成固定格式字符串 | 模板字面量类型 |
| 描述树或嵌套数据 | 递归类型 |
| 只验证配置但不丢失具体推断 | `satisfies` |
| 保留调用处的字面量推断 | `const` 泛型参数、`as const` |
| 区分不同领域的同形字符串/数字 | 品牌类型、`unique symbol` |
| 复用并校验已有函数签名 | `Parameters`、`ReturnType`、`ConstructorParameters` |
| 验证自定义类型工具 | `Expect`/`Equal`、`@ts-expect-error` |
| 设计生产级泛型库 | 先理解方差，再谨慎使用 `in`/`out` |

## 20. 综合练习（附思路）

<a id="subsection-exercise-1"></a>
### 练习一：只读字段提取

实现 `ReadonlyKeys<T>`，取得类型中被声明为 `readonly` 的键。

思路：TypeScript 的结构赋值规则对 `readonly` 比较宽松，直接用两个对象类型做简单的双向 `extends` 比较并不可靠。应对每个键构造一个单属性类型：用 `Pick<T, K>` 保留原来的 `readonly`，再与移除修饰符后的 `{ -readonly [P in K]: T[P] }` 比较；可以复用 `Equal`/`IfEquals` 技巧筛选出差异键。一个参考骨架是：

```ts
type IfEquals<X, Y, A = X, B = never> =
  (<T>() => T extends X ? 1 : 2) extends
  (<T>() => T extends Y ? 1 : 2)
    ? (<T>() => T extends Y ? 1 : 2) extends
        (<T>() => T extends X ? 1 : 2)
      ? A
      : B
    : B;

type ReadonlyKeys<T> = {
  [K in keyof T]-?: IfEquals<
    Pick<T, K>,
    { -readonly [P in K]: T[P] },
    never,
    K
  >;
}[keyof T];
```

这个练习会涉及修饰符比较，难度高于前面的工具；应结合具体 TypeScript 版本编译验证，不要把普通赋值测试当成 `readonly` 的可靠判据。

<a id="subsection-exercise-2"></a>
### 练习二：事件处理器生成

把下面的事件配置转换为处理器类型：

```ts
type Events = {
  login: { userId: string };
  logout: undefined;
  error: { message: string; code: number };
};
```

目标：生成 `onLogin`、`onLogout`、`onError`，并让参数类型自动对应。

<a id="subsection-exercise-3"></a>
### 练习三：分页响应

定义：

```ts
type Page<T> = {
  list: T[];
  total: number;
};
```

再实现 `DataOf<T>`，使 `DataOf<Page<User>>` 得到 `User`，而 `DataOf<User>` 得到 `never`。

参考实现：

```ts
type DataOf<T> = T extends Page<infer Item> ? Item : never;
```

### 练习四：类型安全接口表

定义路径到响应的映射，并实现：

- [ ] `const` 泛型参数什么时候比 `as const` 更方便。
- [ ] 协变、逆变、不变，以及 `in`/`out` 标注不应被滥用。
- [ ] 品牌类型如何区分结构相同但业务含义不同的值。
- [ ] 如何用 `Expect`、`Equal` 和 `@ts-expect-error` 测试类型工具。

如果只会使用工具类型，却不能解释联合分布、`never` 消除和 `T[K]` 的推导过程，说明还需要回到对应小节练习。类型越复杂，越应该先画出中间类型，再阅读最终结果。

<a id="section-summary"></a>
## 小结

高级类型可以归纳成一条链：

```text
typeof 取得值的类型
  ↓
keyof 取得类型的键
  ↓
T[K] 取得键对应的值类型
  ↓
映射类型遍历并变换属性
  ↓
条件类型按规则选择分支
  ↓
infer 从结构中提取内部类型
  ↓
模板字面量生成格式化键名
  ↓
递归类型处理嵌套结构
```

掌握这条链后，遇到新的类型工具时，可以先拆解它“遍历了什么、判断了什么、提取了什么”，而不必死记每个复杂定义。
