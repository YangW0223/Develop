# 07. 高级类型工具

高级类型的目标是从已有类型推导新类型，减少重复并保持模型同步。

## 1. `typeof`：从值获取类型

```ts
const defaultConfig = {
  theme: "light",
  pageSize: 20,
  showTips: true,
};

type Config = typeof defaultConfig;
```

类型位置的 `typeof` 不同于 JavaScript 运行时的 `typeof`。它让配置对象成为唯一事实来源。

## 2. `keyof` 与索引访问类型

```ts
type User = {
  id: number;
  name: string;
  active: boolean;
};

type UserKey = keyof User;     // "id" | "name" | "active"
type UserName = User["name"]; // string
type UserValue = User[keyof User]; // number | string | boolean
```

数组元素类型也能提取：

```ts
const roles = ["admin", "editor", "viewer"] as const;
type Role = (typeof roles)[number];
```

## 3. 映射类型

遍历已有类型的键并生成新类型：

```ts
type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};

type MyOptional<T> = {
  [K in keyof T]?: T[K];
};
```

可用 `-?`、`-readonly` 移除修饰符：

```ts
type RequiredMutable<T> = {
  -readonly [K in keyof T]-?: T[K];
};
```

## 4. 常用内置工具类型

```ts
type User = {
  id: number;
  name: string;
  email?: string;
};

type UserPatch = Partial<User>;             // 全部可选
type CompleteUser = Required<User>;          // 全部必填
type ReadonlyUser = Readonly<User>;          // 全部只读
type UserPreview = Pick<User, "id" | "name">; // 选择字段
type UserWithoutId = Omit<User, "id">;       // 排除字段
type UsersById = Record<number, User>;        // 键值映射
type Present = NonNullable<string | null>;    // string
```

函数相关工具：

```ts
function createUser(name: string, age: number) {
  return { id: crypto.randomUUID(), name, age };
}

type CreateArgs = Parameters<typeof createUser>; // [string, number]
type CreatedUser = ReturnType<typeof createUser>;
```

工具类型是浅层变换，`Partial<User>` 不会自动让嵌套对象内部也变成可选。

## 5. 条件类型

条件类型像类型层面的条件表达式：

```ts
type IsString<T> = T extends string ? true : false;

type A = IsString<"hello">; // true
type B = IsString<number>;  // false
```

一个实用例子：解除 Promise 包装。

```ts
type UnwrapPromise<T> = T extends Promise<infer Value> ? Value : T;

type A = UnwrapPromise<Promise<string>>; // string
type B = UnwrapPromise<number>;          // number
```

`infer` 在条件成立的分支中声明待推断类型变量。标准库已提供递归处理的 `Awaited<T>`。

## 6. 分布式条件类型

泛型条件类型接收联合类型时，会分别作用于每个成员：

```ts
type ToArray<T> = T extends unknown ? T[] : never;
type Result = ToArray<string | number>; // string[] | number[]
```

若不希望分布，在两边套元组：

```ts
type ToArrayTogether<T> = [T] extends [unknown] ? T[] : never;
type Result = ToArrayTogether<string | number>; // (string | number)[]
```

## 7. 模板字面量类型

```ts
type EventName = "click" | "focus";
type HandlerName = `on${Capitalize<EventName>}`;
// "onClick" | "onFocus"

type ApiPath = `/api/${"users" | "products"}/${number}`;
const path: ApiPath = "/api/users/1";
```

它适合事件名、路由、国际化 key 等具有固定格式的字符串。不要构造巨大联合，否则会拖慢类型检查。

## 8. 键重映射

映射类型可用 `as` 改变键名：

```ts
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type UserGetters = Getters<User>;
// { getId(): number; getName(): string; getEmail(): string | undefined }
```

也能通过映射为 `never` 删除键：

```ts
type WithoutKind<T> = {
  [K in keyof T as K extends "kind" ? never : K]: T[K];
};
```

## 9. `as const` 与 `satisfies` 配合

```ts
type Route = { path: `/${string}`; auth: boolean };

const routes = {
  home: { path: "/", auth: false },
  admin: { path: "/admin", auth: true },
} as const satisfies Record<string, Route>;

type RouteName = keyof typeof routes; // "home" | "admin"
```

`as const` 保留字面量并加上只读，`satisfies` 验证每一项符合 `Route`。两者用途不同，可以组合。

## 10. 复杂类型的边界

高级类型应让调用代码更简单，而不是展示技巧。如果错误提示难以理解、类型计算明显变慢，或者一段类型比直接定义模型更难维护，就应该拆分或回到清晰的显式类型。
